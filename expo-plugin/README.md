# app-mcp-expo-plugin

Expo config plugin that embeds the `macos-ui-mcp` harness (`swift-harness/`) in your
app's **Debug** iOS build, so Claude can drive it in the Simulator. Because `ios/` is
regenerated by `expo prebuild`, the plugin reapplies the changes on every prebuild —
nothing to edit by hand.

On prebuild it:

- adds `pod 'AppMCPHarness', :path => '…/swift-harness', :configurations => ['Debug']`
  to the Podfile — Release builds don't link the harness;
- adds `#if DEBUG import AppMCPHarness #endif` to `AppDelegate.swift` and calls
  `AppMCP.start(port:)` (behind `#if DEBUG`) first thing in
  `application(_:didFinishLaunchingWithOptions:)`.

Release builds neither compile nor link the harness and never open the port. In Debug
it listens on `127.0.0.1` only.

## Install

The plugin finds the harness through its own real path, so install it as a link to
this checkout (not a copy):

```sh
# pnpm (link: keeps the real path)
pnpm add -D app-mcp-expo-plugin@link:../../../app-mcp/expo-plugin

# npm (file: directories are symlinked)
npm install -D app-mcp-expo-plugin@file:../path/to/app-mcp/expo-plugin
```

If it's copied instead (or you keep the harness elsewhere), pass `harnessPath`.

## Configure

```js
// app.config.js
module.exports = ({ config }) => ({
  ...config,
  plugins: [
    ...config.plugins,
    ["app-mcp-expo-plugin", { port: 8787 }],
  ],
});
```

| Option | Default | |
|---|---|---|
| `port` | `8787` | Must match `MACOS_UI_MCP_HARNESS_URL` in the MCP server config. |
| `harnessPath` | `<plugin>/../swift-harness` | Folder containing `AppMCPHarness.podspec`. |

## Run

```sh
npx expo prebuild -p ios
npx expo run:ios
```

Then in Claude: `launch_app` isn't needed (`expo run:ios` already started it), so go
straight to `get_ui_tree`, `click`, `type`, `scroll`, `screenshot`. To install a build
yourself instead, use `launch_app(path: ".../Debug-iphonesimulator/App.app",
simulator: "booted")`. Metro must be running for a Debug build to load its JS.

## Targeting React Native views

- `testID` becomes the node id: `<Pressable testID="save">` → `#save`.
- `"Label"` matches `accessibilityLabel` and visible `<Text>`. A Pressable takes its
  label from the Text inside it, so `click("Save")` resolves to the Pressable and taps
  it with a real touch.
- Elements on a screen covered by the next one are `hittable: false` and lose to the
  visible match.

Only a Swift `AppDelegate` (Expo SDK 50+) is supported.
